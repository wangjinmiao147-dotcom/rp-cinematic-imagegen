# 本地 ComfyUI、角色 LoRA 与参考图指南

适用于 **v2.9.63 本地候选**，尚未上传 GitHub。公开的 v2.9.62 没有本指南描述的新配置入口；请使用对应本地候选测试，不要以公开下载包是否出现这些选项判断安装失败。

## 安装本地候选

先把当前扩展文件夹备份到酒馆扩展目录之外。解压候选插件 ZIP，将其中 `rp-cinematic-imagegen` 文件夹内的文件放入原插件目录（通常为 `public/scripts/extensions/third-party/rp-cinematic-imagegen`），完成后重启酒馆并刷新页面，确认界面显示 v2.9.63。保持一个插件目录，避免同时加载新旧两份。

本地候选需要手动安装；现有 GitHub 安装器与酒馆在线更新会获取公开版本，不能用它们安装这份未上传的候选。参考图库保存在本浏览器，覆盖文件前可先导出参考图包；LoRA 与姓名设置保存在插件设置中。回退时还原备份的插件文件并刷新。

## 先准备能单独运行的 ComfyUI

按 [ComfyUI 官方 Windows 安装说明](https://docs.comfy.org/installation/desktop/windows) 或自己的现有安装方式准备服务。先在 ComfyUI 自己的页面运行一张测试图，确认模型可加载。插件负责选择模型和提交工作流，不安装 ComfyUI，也不下载任何模型或 LoRA 权重。

下面目录以普通 ComfyUI 安装为例；桌面版或已有共享模型目录按实际配置使用。ComfyUI 支持按类别管理模型并通过配置引用外部目录，详见 [官方模型目录说明](https://docs.comfy.org/basic-concepts/models)。

| 文件用途 | 常见目录 | 本候选中的选择项 |
| --- | --- | --- |
| SD / SDXL Checkpoint | `ComfyUI/models/checkpoints` | Checkpoint 模型 |
| Qwen 编辑扩散模型 | `ComfyUI/models/diffusion_models` | 扩散模型 |
| Qwen 文本编码器 | `ComfyUI/models/text_encoders` | 文本编码器 |
| Qwen VAE | `ComfyUI/models/vae` | VAE |
| 角色 LoRA | `ComfyUI/models/loras` | 角色 LoRA 的文件名 / 服务器列表 |

模型文件必须与工作流和底模相匹配。SD1.5、SDXL 和 Qwen 的 LoRA 不能仅靠改名互相通用；本候选只区分 SD 与 Qwen 类别，SD 内部具体底模仍需自己核对。目录正确也不表示文件完好或显存足够。

## 在酒馆中连接与选择预置

1. 在插件设置中把图片后端选为 ComfyUI，填入你实际运行的服务地址。同一台电脑且使用默认端口时，常见地址是 `http://127.0.0.1:8188`；以 ComfyUI 页面实际地址为准。
2. 选择工作流类型，点击“检测连接并读取模型”。该按钮只查询节点和模型列表，不提交图片生成。
3. 按界面提示选择所需模型。缺少节点、输入或文件时先在 ComfyUI 中处理，再重新检测；切换服务后重新读取，旧服务器的列表不能代表新服务器。
4. 先用单人、少量参考图测试，核对预览名单与参考编号，再确认生图。需要排错时用插件的“导出错误报告”。

手机浏览器的 `127.0.0.1` 指向手机自身；连接电脑服务需使用实际可达的电脑地址和相应服务配置。浏览器报 CORS、混合内容或连接失败时，检查酒馆页面与 ComfyUI 地址、浏览器 Network 和服务终端，不能仅凭报错判断模型不支持编辑。

| 工作流选项 | 合适场景 | 单次参考图 | 所需模型 |
| --- | --- | ---: | --- |
| 自定义工作流 | 保留已有 API JSON 与节点配置 | 当前适配最多 1 张 | 由你的工作流决定 |
| SD 基础文生图 | 依文字和可选 LoRA 绘图 | 0 | 兼容的 Checkpoint |
| SD 单图图生图 | 以一张原图为底重绘 | 1 | 兼容的 Checkpoint |
| Qwen 原生多图编辑 | 用不同人物的独立参考图编辑剧情 | 1–3 | 兼容的扩散模型、文本编码器、VAE |

选择 SD 基础文生图后，需要自行把画风偏好从“参考图驱动”改为“跟随角色卡画风”等非参考模式。它不读取身份图；保留参考图驱动会明确提示冲突，避免误以为已经送入照片。SD 图生图可调整“参考图改动幅度”，数值越大改动越多；先核对原图与实际效果。节点与参数原理见 [官方文生图教程](https://docs.comfy.org/tutorials/basic/text-to-image)。

Qwen 预置使用 `TextEncodeQwenImageEditPlus` 的三个图片入口，需要支持该节点的 ComfyUI 和相匹配的编辑模型。模型准备可参考 [官方 Qwen 编辑教程](https://docs.comfy.org/tutorials/image/qwen/qwen-image-edit)；多图 Plus / 2509 文件组合与节点以 [ComfyUI 官方 Qwen 2509 模板](https://github.com/Comfy-Org/ComfyUI/blob/master/blueprints/Image%20Edit%20%28Qwen%202509%29.json) 为例。不要把普通 Qwen 文生图模型或其他不兼容权重仅因名字相似放进编辑预置。

采样参数可以留空，采用预置默认值；固定随机种子用于复现同一配置，`-1` 为随机。Qwen 的当前预置没有自动加载加速 LoRA；自行准备的角色 LoRA 也不等于加速模型。生成速度与显存需求取决于实际 GPU、模型精度、画幅和图片数量。本候选已真实验证 DreamShaper8 LCM 内置文生图与基础图生图，其他模型与 LoRA 效果尚未验收。

## DreamShaper8 LCM 等快速模型

选择 SD 基础文生图或 SD 单图图生图，Checkpoint 选择实际 LCM 模型，再将“Checkpoint 采样方式”选为“LCM 快速模型”。插件会自动生成 LCM 模型采样节点与 LCM 采样器，不需要粘贴旧工作流 JSON 或填写节点编号。普通 SD 模型仍使用“普通 SD”。

步数、引导强度留空时，LCM 默认 8 步、CFG 2。切模式不会覆盖你以前填过的数值；若曾填 28 步、CFG 7，请自行清空或调整。LCM 的默认画幅为：1:1=512×512、16:9=768×448、9:16=448×768、2.39:1=768×320。

使用 DreamShaper8 LCM、RTX 3060 Laptop 6GB 实测，移除已有工作流文件并禁用外部参考节点后，内置文生图 512×512 约 5.2 秒，内置单图图生图约 2.7 秒。计时包括模型能力读取、提交、轮询和图片下载，不含剧情文字分析；这两次样本不代表所有场景速度。模型作者的 LCM 配置说明见 [DreamShaper8 LCM 模型卡](https://huggingface.co/Lykon/dreamshaper-8-lcm)。

基础图生图用于以原图重绘，不能保证精确锁脸、指定动作或道具。单张参考容量和单人 LoRA 范围不因选择 LCM 而增加；多人分区参考试验仍出现合人或分栏，不能据此宣称多人 LoRA 已支持。

## 分开卡片标题与人物真名

形象工作台先选择绑定角色，再查看“角色真实姓名与别名”。例如卡片标题可以是“车站奇遇合集”，人物真名是“林岚”；标题用于区分卡片，真名和别名用于理解本轮剧情中人物的对应。

- 已知真名：填写真实姓名，别名用逗号分隔，再保存。姓名最多 100 字符，别名最多 20 项，每项最多 100 字符。
- 希望由模型判断：真实姓名留空，AI 根据正文、角色资料和当前场景确认人物，标题本身不证明人物姓名。
- User：沿用酒馆当前用户名，不在角色真名输入中另设玩家姓名。

参考图与 LoRA 始终绑定头像标识。同名卡片不会互相复制配置，改显示名不会把参考图移到另一张卡片；若更换头像文件标识，相当于另一个绑定，应检查对应资料。保存使用界面当前显示角色的标识，切换角色后重新核对字段。

## 给单个角色绑定 LoRA

先将与底模匹配的 LoRA 放入 `models/loras` 或已配置的共享 LoRA 目录。安装与加载机制可查看 [ComfyUI 官方 LoRA 教程](https://docs.comfy.org/tutorials/basic/lora)。插件不会把权重作为图片上传，也不会训练 LoRA。

在形象工作台选择角色，填写相对文件名，例如 `people/linlan.safetensors`，也可从检测后读取的服务器列表中选择。不要填写网址、绝对磁盘路径或 `../` 路径。确认 SD / SDXL 或 Qwen 类别、模型说明要求的触发词，然后启用并保存。

模型强度和文本强度默认均为 `0.8`，有效范围 `0–2`；触发词最多 200 字符。SD 预置使用模型与文本两项强度，Qwen 预置使用模型 LoRA，文本强度在此预置不参与加载。具体合适的强度应按 LoRA 作者说明和成图结果调整。

绑定只在 **ComfyUI 内置预置、一个独立人物入镜、已启用且文件名有效、类别匹配** 时加载。普通 LoRA 影响整张图，多人场景会提示跳过所有角色 LoRA，不叠加不同人物 LoRA。其他后端、自定义工作流或类别不匹配也会提示跳过，继续普通生图；若需要自定义工作流中的区域 LoRA，需自行在该工作流实现，本候选不自动添加区域遮罩。

## 从群像标注并另存独立参考图

使用参考图的标注 / 裁剪入口，在图片上拖动框选一个人物区域，选择归属人物、参考图名称和用途，例如人物区域、完整角色或面部特写。按需勾选“设为该角色主图”，点击“另存角色参考图”。

完整原图保留，新裁切图加入所选人物的参考图库。编号、姓名和框线仅用于标注预览，不会写进新图片。群像里两个人分别使用自己的裁切参考，不把同一群像未经区分地同时当作两个人的主身份图。需要两人时分别框选并保存两次；这一步由用户确认归属，不会自动识别全图所有人物。

主身份图用于绑定身份，其他视图补充脸部、服装和造型。裁切脸部作为辅助图时，应保留一张能表达人物整体身份的主图；“参考图类型”是用途提示，不会自动证明某个区域属于谁。

## 核对本张参考容量

Qwen 内置编辑最多 3 张，SD 图生图只有 1 张，基础文生图为 0 张。剧情分析先判断真实入镜主体和互动者，不把整个群聊成员表当作出镜名单。程序保留每位入镜人物主图，剩余容量再选择辅助图；特写可优先脸部辅助，全景可使用相应造型图。

例如双人 Qwen 镜头先各分配一张主身份图，第三个位置可用于合适的辅助图。人物有多个别名、画面有照片或倒影，不因此增加一个独立人物。明确要求四个人同时入镜而后端只有三张身份参考容量时，会提示处理，不能静默少画人；应改用容量合适的后端或明确调整镜头要求。

## 常见排错

| 现象 | 优先检查 |
| --- | --- |
| 检测连不上 | 服务是否运行、URL 和端口是否正确、浏览器是否可访问、CORS / HTTPS 与 HTTP 配置 |
| 列表没有模型 | 文件类别与目录、ComfyUI 是否已识别文件、是否读取了当前服务器 |
| 缺 `TextEncodeQwenImageEditPlus` 等节点 | ComfyUI 版本、启动时节点导入错误，以及实际使用的官方模板版本 |
| 基础文生图提示参考模式冲突 | 切换到非参考图驱动画风，或选择真正的编辑 / 图生图预置 |
| LoRA 未加载 | 本次是否多人、后端及预置是否支持、类别及底模是否匹配、是否已启用且保存 |
| 参考图数量不够 | 入镜名单是否准确、每位人物是否有独立主图、当前预置容量是否足够 |
| 标注无法保存 | 是否已框选有效区域、归属是否正确、图片是否可读取，取消后重新打开原图 |
| 已检测就绪仍生成失败 | 服务终端中的权重加载、显存、节点执行和实际输入错误；检测只验证服务声明的节点与文件名称 |

需要反馈时，先导出默认错误报告。默认报告不含剧情、角色名、密钥、图片或服务地址；如手动开启文字诊断，分享前查看自己附带的剧情与提示词。报告只下载到本机，不自动发送。


## 一张卡包含多个人物

在形象工作台的“一张卡内的独立人物”中添加真实姓名、别名和外貌，保存后选择具体人物，再上传并设★主图。每人有独立图库，修改姓名不会改绑定。世界卡标题只是卡名，单人参考图生成需要先选具体人物。AI仍按正文判定出场，名单不会自动全员入镜。

本地SD的“多人参考排布（实验）”只接受2–4个人物各自的一张主图，适合3:4全身立绘；根据发送顺序从左到右排布。不加载多人LoRA，不使用外部节点。旧SD底模更适合简洁英文外貌描述。实测DreamShaper8 LCM无法可靠完成递书与身份保持，这个选项用于试验，不建议作为稳定多人剧情方案。可先用支持多参考的图片接口完成主流程验收。
