# v2.9.62 修复第 3 步人物姓名误判

修复用户反馈的“第 3 步没有保留已核对的规范人物姓名，已停止生图”。继承 [v2.9.61](RELEASE_v2.9.61.md) 的全部维护修复与错误报告功能。

## 修复行为

旧版用 `edit_instruction.includes(规范姓名)` 检查第三步英文指令。模型把“林岚”写为“Lin Lan”“小岚”“林澜”，或单人画面写“she”，即使指的是已确认的同一人物，也会停止；开启本地回退时还会无意义地重做该阶段。

本版取消这条字符匹配，由现有第三步模型结合已核对的演员表、别名、剧情、动作归属和可见范围判断人物对应。多人物互动优先使用清楚的姓名指代，称呼变化不作为新增人物。没有新增模型调用、强制输出字段或模糊匹配改名。

实际卡片和参考图仍按第二步确认的身份绑定，不从第三步自由文字猜卡片。最终提示保留入镜身份索引并说明别名、译名和代词指向这些同一人物。JSON、空指令、真实拒绝、入镜依据、核心身份/动作冲突、缺身份参考、取消与来源变化的现有检查继续生效。

## 更新与验证

在酒馆扩展管理中更新并刷新即可。只有使用可选本地剧情代理的用户需要同时更新本地服务 ZIP 并重启，代理的输出前提示也已同步放宽自由描述中的姓名要求，结构化人物槽仍按原协议绑定。

回归验证译名、昵称、轻微错字、单人代词不再误停；云端有效结果只请求一次，不启动本地回退。执行实际生成流程，验证双人参考仍分库、局部人物范围保留、总文字阶段数仍为三次，空指令不请求图片后端。测试使用虚构输入与模拟服务；模型是否正确理解复杂多人动作仍依赖输出质量，可通过预览检查及错误报告反馈。
