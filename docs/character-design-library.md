# 角色视觉判断库

本库让事实提取、人物关系核验与图像编辑三个AI阶段参考同一份角色设计知识。它帮助AI结合剧情语义、已确认状态及实际提供的参考理解当前身体，不根据“猫”“蛇”“亡魂”等关键词运行分类器，也不替用户补一套物种外观。

规则的唯一来源是 [`src/character-design-library.js`](../src/character-design-library.js)。`buildCharacterDesignGuidance(stage)` 从导出的数据逐项组装中文参考，已经由 `src/prompts.js` 加入三个阶段的实际系统提示词。`index.js` 把现有候选角色资料交给关系与编辑阶段供理解；资料不能证明入镜或当前动作，也不能成为剧情证据。文字模型没有收到图片时，不声称看过参考图；未变视觉设计仍由实际图像参考负责。库不按角色名分支，不生成traits对象，不新增输出JSON字段或生图校验门槛，不增加文字调用次数。

## 修改位置

- `CHARACTER_DESIGN_STAGE_ROLES`：三个阶段的职责边界。
- `CHARACTER_DESIGN_COMMON_RULES`：证据、当前形态优先、可见范围、普通人类肢体适用范围与未知项处理等共通规则；每条提供 `fact`、`relation`、`editor` 三个长度不同的版本。
- `CHARACTER_DESIGN_PROFILES`：以下八种判断参考，每项含稳定 `id`、中文 `label` 和三个阶段的短规则。新增或修改知识在这里完成，不复制一套独立提示词到调用方。

| id | 判断参考 | 需要区分的事情 |
| --- | --- | --- |
| `human` | 人类 | 自然人类肢体与有依据的缺失、假肢、特殊结构；遮挡与结构不存在。 |
| `transformed_yokai` | 化形妖怪 | 妖怪本体与当前人形；化形不自动添加本体特征，也不自动删除已确认耳、尾、翼。 |
| `animal_hybrid` | 兽娘等混合形 | 猫、狗、狐狸等身份与各自有依据的耳、尾、爪、足型和数量。 |
| `serpent_humanoid` | 蛇类人形 | 蛇身份与当前人形；闭口时的可见性；竖瞳、尾巴和鳞片各自的证据。 |
| `nonhuman_topology` | 人外下半身与额外肢体 | 当前蛇尾、人鱼尾、马身等下半身拓扑，以及有依据的额外肢体连接与任务。 |
| `animal_form` | 当前动物形态 | 四足、鸟类、鱼类等当前动物身体；能说话或具有人格不自动成为人形。 |
| `artificial_body` | 机械、仿生与人偶 | 已确认人工结构与材质；不自动显露机械骨架、提线或新增关节。 |
| `supernatural_identity` | 亡魂、精灵等超自然身份 | 身份和物种年岁与当前实体外观；虚影、透明、发光等效果只用明确剧情状态。 |

表格用于定位维护入口，完整生效措辞仍以模块数据为准。修改后运行 `node --test tests/character-design-library.test.mjs`；测试直接调用公开builder，并核对输出包含当前数据定义、各阶段职责及关键设计边界。新增profile时同时补充此表和相关语义测试。

## 三个阶段怎么使用

`buildCharacterDesignGuidance('fact')` 的篇幅最短；`'facts'` 是同一阶段的别名。事实阶段只提取所选瞬间已经生效的身体动作、状态或变化，使用既有动作/状态与证据字段，不能增加 `species`、`traits`、`current_form` 等JSON键。身体变形也不能为了持久化而硬塞到服装或道具更新中。

`buildCharacterDesignGuidance('relation')` 用于核对身体归属、当前形态下的肢体任务、接触与入镜范围。它不重新选帧或设计人物，不把尾巴、翅膀等已确认部位当成新增演员。只有实质的动作归属或接触矛盾才按原协议处理；普通未说明设计不新增冲突或生成阻断。

`buildCharacterDesignGuidance('editor')` 是默认版本。编辑阶段根据已经核验的事实，只写本轮动作、必要变化与容易被旧参考覆盖的明确保持项。它不重新复述物种档案、五官、画风或身份模板，也不把本库全文送成图像提示词。未识别的stage安全回退到这个版本，不阻断调用。

## 怎么判断当前设计

先定位所选瞬间，再确认已经生效的当前形态。明确变形结果优先于旧参考的身体拓扑；未来会变形、妖怪的本体、物种年岁都不能代替当前身体事实。没有发生变化的已确认设计仍保留，包括混合形的人类身体与非人类局部。

具体左右、尾巴等部位、数量、瞳孔形状和身体效果分别需要剧情或实际提供的参考依据。某个阶段没有收到参考图时，只能使用输入明确说明的设计，不声称看过图，也不猜隐藏结构。看不到的部位可能只是被遮挡或在画外；闭口不会展示舌头，但不表示设计中没有舌头。

普通手脚规则只应用于已确认的人类形肢体，并保留当前遮挡；每只普通人类脚的结构总数是五趾（一大趾四小趾），但本镜头不必全部可见，不把重叠轮廓画成额外脚趾。有尾、鳍、蹄或额外肢体时按其已确认拓扑判断。未说明的traits、`unknown`、`null`不变成可见特征，不补猜、不逐项当冲突，也不新增生成门槛。

还原以角色设定、当前剧情和参考画风为准。插画允许按原图简化纹理和小轮廓，不强求真人质感或极细解剖；结构数量、连接和动作归属仍须合理。角色性别或身体设计不能根据发长、衣服、胸围或物种名猜测。提示词与代码检查通过只证明规则已传入，不能保证模型每张图都按规则画对；成图需单独检查。

### 案例一：有依据的猫耳与猫尾

输入已明确参考设计含一对猫耳、一条猫尾，当前正文写尾巴轻扫椅背。AI保留这些已确认部位，提取并核验尾巴的当前动作和接触；若尾巴被椅背遮挡，保持遮挡。只有“猫族”称谓而没有尾巴依据时，不自行加尾。当前人形也不自动删掉已有依据的猫耳猫尾。编辑指令描述本轮尾巴动作即可，不扩写猫爪、兽首、多尾等外观套餐。

### 案例二：化形蛇类，仅确认竖瞳且闭口

输入说明当前是人形，原设明确竖瞳，所选瞬间嘴唇闭合；没有蛇尾、鳞片或其他本体特征依据。AI保留竖瞳设计和当前闭口状态，不画蛇舌，不自行添尾、鳞片或蛇首。若竖瞳本轮没有变化，编辑阶段也不用复述整套眼睛身份规则；参考图负责保留未改变设计。若原设未确认竖瞳，蛇身份本身不能补出竖瞳。

### 案例三：当前为蛇尾下半身

所选瞬间已明确下半身是蛇尾，正文写尾巴盘绕石柱；“稍后化成人形”尚未发生。关系阶段按蛇尾连接、盘绕和接触核验；编辑阶段描述当前尾巴任务，不能为人类站姿或两腿常模补画两条人腿。只有所选瞬间明确已经变成人腿时才更新相应拓扑，并保留仍有依据的其他设计。
