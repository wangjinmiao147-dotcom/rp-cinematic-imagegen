# v2.9.63：多人物管理、内置工作流与参考图修复

发布日期：2026-10-14。基于v2.9.62，支持按故事卡内的独立人物管理参考图，并让本地生图参数和基础工作流更容易配置。

## 人物与参考图

- 一张世界卡或故事卡可创建多个独立人物，各自保存真实姓名、别名、外貌与参考图。人物改名保留内部ID和图像绑定；卡片标题不再自动当作人物姓名。
- AI依据当前正文判断实际入镜名单，被提及、画外或已离场的角色不自动加入。按后端容量优先上传每位入镜人物的主身份图，缺身份图或容量不足时明确停止。
- 参考图支持框选人物区域、另存到对应人物图库，保留原图；姓名与编号仅出现在标注预览。修复主图星标、标注和删除按钮重叠。
- Gemini实际统一编辑分支为每张主图发送身份、肤色、体型和相容衣装说明；普通颜色/衣装类别描述不授权重新设计，已核验的新衣装优先。参考姿势与持物状态不作为当前剧情事实。

## 本地生图与LoRA

- ComfyUI新增连接/节点检测、已安装模型选择，以及SD文生图、单图图生图、Qwen原生编辑预置；原自定义API工作流继续可用。模型权重需自行准备，不自动下载。
- SD支持普通/LCM采样；LCM必须搭配对应模型权重。Qwen内置编辑预置最多3张参考图。SD多人参考排布可处理2–4位主图，使用核心合成与分区文本节点，属于实验功能。
- 单角色LoRA默认关闭，仅在受支持的ComfyUI内置预置、单人入镜且配置有效时加载；多人场景跳过并提示。多人LoRA尚未提供，本机未找到角色LoRA权重，不能把功能测试称为效果验收。
- 主设置直接选择本地宽/高和步数。Qwen桥接、SD接口、ComfyUI内置流程接受256–2048范围内32倍数像素；手动尺寸关闭自动升档，预览显示实际推理尺寸和步数。非法像素在读取参考图、上传或运行模型前拦截。自定义工作流使用其JSON参数。

## 流程与错误修复

- Gemini使用原生imageConfig画幅配置，跳过thought=true思考草图，只保存最终图片；只有草图时明确报错。
- SD从统一模板中先提取实际剧情与保持项，避免长规则占用短CLIP文本窗口。云端指令将当前动作、保持项、排除项和演员映射提前，各段只出现一次；本地Qwen保持原指令顺序。
- 同一正文中完整、唯一且有序的省略引文可恢复原文；虚构、反序、重复或词内拼接仍拒绝。失败校验前保存各阶段原始返回。
- 普通分析采用中性事实说明，不改写当前剧情；拒绝、额度/限流和密钥错误分别提示，不把失败返回当成生图指令。被拒绝的内容不自动改写或反复提交。
- 默认错误报告仅含脱敏枚举、错误码、计数、尺寸与耗时，不含剧情、名字、模型名、图片、密钥、地址或本机路径；文字诊断需手动开启，报告仅下载到本机。

## 验证范围

755/755回归通过，0失败、0跳过；覆盖真实Edge/jQuery、IndexedDB、任务快照、取消/队列、多人参考图、参数透传、接口协议和窄屏布局。

真实酒馆使用自有反代测试Gemini双人/四人、六种双人组合和四人旧图切双人，核对实际上传主图与保存最终图的字节哈希。后续外观复测保住肤色、原长裙和主要饰件；错字与别名不增加人物。分析请求使用3.8Flash，实际返回模型由反代路由决定。

本地Qwen Image2.1桥接在512×288、20/24步测试双人/四人，保住主要设计，场景与部分动作仍有偏差。DreamShaper8 LCM能执行内置流程，但多人外观与互动仍不可靠。没有把排布称为精准多人锁脸或多人LoRA。

指定左右手、竖握法杖、按剑鞘及复杂接触尚不能保证稳定遵循；部分普通原文仍可能被上游文字接口拦截。原失败结果保留，不以一次改善宣称精确80%或90%的遵循率。手机实机、其他硬件/模型和角色LoRA效果未验收。
