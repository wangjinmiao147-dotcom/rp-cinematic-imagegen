# 🎬 RP 电影配图

面向 [SillyTavern](https://github.com/SillyTavern/SillyTavern) 的角色扮演配图扩展，依据当前剧情、实际入镜人物和各自参考图生成剧情剧照、表情特写、角色设计图，在聊天与图库中管理结果。

当前版本：**v2.9.57**。MIT 许可证；由 RP 电影配图 contributors 维护。模型与依赖出处见 [第三方说明](THIRD_PARTY_NOTICES.md)。

![实际发布模块的公开演示工作台](docs/images/public-workbench-v2.9.57.png)

截图使用虚构夹具和隔离的宿主接口，展示实际发布模块的工作台；未调用模型，不是生成图片质量验收。

## 安装

普通用户只安装扩展并配置文字、图片接口，**不需要安装 Ollama 或 9B 模型**。

### 从 GitHub 安装（推荐）

1. 打开 SillyTavern → 扩展 → 安装扩展。
2. 粘贴 `https://github.com/wangjinmiao147-dotcom/rp-cinematic-imagegen`。
3. 安装后刷新页面并启用“RP 电影配图”。以后从扩展管理界面更新。

### ZIP 手动安装

1. 从 [v2.9.57 Release](https://github.com/wangjinmiao147-dotcom/rp-cinematic-imagegen/releases/tag/v2.9.57) 下载 `rp-cinematic-imagegen-v2.9.57.zip`。
2. 解压得到 `rp-cinematic-imagegen` 文件夹，放入 `<SillyTavern 根目录>/data/<用户>/extensions/`（默认用户为 `default-user`）。
3. 刷新页面并启用扩展。避免解压成扩展目录内的第二层同名文件夹。

### 酒馆助手安装器

已安装酒馆助手（JS-Slash-Runner）的用户可下载同一 Release 中的 `rp-cinematic-imagegen-tavern-helper-installer-v2.9.57.json`，在“酒馆助手 → 脚本库”导入为全局脚本并确认启用，使用“安装 / 更新 RP 电影配图”按钮。

JSON 是安装器，实际运行的是原生扩展。安装器先安装正式目录，再处理旧目录 `rp-cinematic-v2`；配置键仍为 `rp-cinematic-imagegen`，优先保留已有正式设置。迁移前可备份酒馆数据，不要公开备份或密钥。

## 首次配置与使用

1. 文字模型选择复用酒馆当前 LLM，或填写独立 OpenAI 兼容接口、模型和自己的密钥。
2. 选择图片后端，配置地址、模型等信息；文字与图片接口分别配置。
3. 导入各人物自己的参考图，指定 ★ 主身份图。User 三视图 / 多视角参考使用独立图库。
4. 点击 AI 消息的 🎬 按钮，或桌面、手机共用的 🎬 悬浮工作台。
5. 核对预览中的入镜名单、可见范围及最终提示词，必要时修改，再确认生成。当前任务与队列均支持取消。

可公开示例：林岚在车站举左手向周禾示意，周禾站在她身旁拿着行李；被提到的同事不在现场。为两人分别提供参考图，核对人数、行李归属和画幅。此示例为虚构内容，不是私人聊天或生成质量验收。

## 工作流程与功能

- 三阶段分析：剧情事实、人物与动作及空间关系、英文图像编辑指令。最新剧情与明确插画要求决定当前瞬间，后续换装或离场不提前发生。
- 实际入镜名单：卡片存在、群成员身份、最近说话和仅被提及不能独立证明身体入镜；局部参与者保持已确认的可见范围。
- 参考图提供身份和画风；本张动作、服装、持物、视角及背景来自剧情。别名归到同一身份，不混用不同人物的参考图。
- 场景连续性：有有效原文依据的环境、服装和道具状态可继承。关闭“延续造型”后不发送上一张剧情图；未知状态不凭空补齐。
- 心理气泡：当前瞬间有明确内心情绪依据时才添加同角色无字 Q 版表情，证据不足只省略气泡。
- 当前世界书上下文：读取角色卡当前绑定且可用世界书中的对应人物明确年龄字段；旧内嵌副本不覆盖当前绑定内容，冲突字段分别保留，不猜年龄。
- 形象工作台、角色设计、User 三视图、多图导入导出、图库与灯箱。本地 Qwen 支持手动局部精修、原图对照和另存候选。
- 失败重试可复用已完成分析仅重试生图，或重新分析；切换聊天、修改消息、取消或刷新后不沿用不适用缓存。
- 自动剧情检测、任务排队、取消当前任务和清空队列；手机预览使用动态视口和固定操作栏。

规则库及维护示例见 [剧情判断库](docs/prompt-decision-library.md)、[角色视觉判断](docs/character-design-library.md)。

## v2.9.57：可选本地 LLM 回退

默认关闭。开启后每个分析阶段优先主文字接口，拒绝、超时、接口错误或结构校验失败时，只将当前失败阶段交给本地接口，下一阶段重新优先主接口。主动取消不会启动本地推理。本地结果也需通过 JSON、证据、姓名等校验，失败时停止，不把报错当图片提示词。

云端密钥不会发送给本地回退接口。启用后，当前阶段的剧情和分析输入会发送给你配置的回退地址。

源码在 `tools/local-scene-llm`，Release 同时提供独立 `rp-cinematic-local-scene-llm-v2.9.57.zip`。Windows + NVIDIA 环境已验证，其他系统与显卡尚未验证。模型来源、校验值、标签导入、端口、资源限制和启动参数见 [本地服务安装说明](tools/local-scene-llm/README.md)。

代理默认仅监听 `127.0.0.1:11436`，连接本机 Ollama `127.0.0.1:11434`，仅允许酒馆 `localhost:8000` / `127.0.0.1:8000` 的跨域来源。其他酒馆端口需修改 `allowedOrigins`。手机的 `127.0.0.1` 是手机自身，默认方案不能直接供手机远程连接。

插件主接口等待默认 60 秒，本地默认 180 秒并另留 20 秒收尾。代理的 `maxStageSeconds` 单独配置，插件等待时间不会自动修改代理计算上限。

## 清晰绘制、视角与镜面

“清晰绘制，最终512”默认关闭，只用于本地 Qwen 参考模式。普通 16:9 场景内部生成一次 1024×576，再完整缩为 512×288。其他尺寸与姿态条件见 [清晰绘制说明](docs/scene-quality.md)。步数、CFG、种子沿用保存设置；高分辨率更耗时，镜面与倒影继续原绘制档。

玻璃和真正镜面分别处理：地点或玻璃高光不证明存在人物倒影。限定单人贴镜、双人支撑姿态可添加无身份几何引导，触发条件见上述文档。后视图不为展示脸部改变已明确机位或动作。

图像模型仍可能画错镜面、手足、持物、裁切和多人归属。限定场景验证不能代表所有场景；本版发布测试没有新增私人剧情生图或全场景像素验收。

## 图片后端与参考限制

- OpenAI 兼容：无参考图可用 generations，有参考图使用 edits 或服务声明的 Chat / Gemini 图片协议。多图服务需支持相应协议；编辑失败保留错误，不自动删图降级。
- Gemini：使用服务支持的图片协议；官方地址密钥通过 `x-goog-api-key`。
- SD WebUI：需启用 API；现有 img2img 适配器只能使用一张参考图，要求多图时明确停止。
- ComfyUI：需可用服务和 API 格式 Workflow，能力取决于工作流及适配器。
- 酒馆 SD：先配置酒馆自己的图片生成服务。

本地 LLM 服务只补文字分析，不生成图片；私有图片桥接、模型权重和第三方中转服务不随扩展分发。远程接口可能需配置 CORS。

参考图驱动模式要求有效身份参考，第一张或 ★ 主图负责身份和画风。OpenAI Images、Chat 图片、Gemini 提交全部已选的不同参考图，服务端数量限制明确报错。不能保证每次完全锁脸或精确复刻画风。

参考图保存在当前浏览器 IndexedDB，不自动跨设备同步，可通过导出 / 导入迁移。导入支持 JPG、PNG、WebP、GIF 和 JSON 包，单图最多 15 MB，每批最多 10 文件、总计 30 MB。Android 排错及历史实机验证范围见 [Android 文档](docs/android-debugging.md)；自动化回归不代表所有手机实机验证。

## 隐私

仓库和 Release 不包含私人配置、密钥、角色卡、聊天、验收日志、生成图片、模型权重、缓存或 `node_modules`，测试使用虚构夹具。

界面密钥由酒馆保存，按所选接口使用；剧情与参考图会发送给你配置的文字或图片服务。使用第三方服务前自行了解其日志、计费和隐私规则。诊断分享前自行检查，避免公开私人内容。

## 开发与发布

基础扩展运行无需 npm 依赖。开发需 Node.js 18+ 与 Windows PowerShell；自动发布使用 Node.js 20 和 Windows。开发测试依赖 `fake-indexeddb`，可选服务单独依赖 `pinyin-pro` 3.29.4。

```powershell
npm ci
npm run check
npm test
npm ci --prefix tools/local-scene-llm
npm run test:local
npm run build
```

`build` 按明确清单生成基础扩展 ZIP、安装器、本地服务独立 ZIP 及 SHA256，并检查包内容。不同版本的已有包保留。推送 `v*` 标签会由 GitHub Actions 自动创建公开 Release；标签前先确认 main CI 通过。

发布流程和社区稿见 [发布说明](docs/COMMUNITY_RELEASE.md)。贡献与安全问题见 [CONTRIBUTING](CONTRIBUTING.md)、[SECURITY](SECURITY.md)。
